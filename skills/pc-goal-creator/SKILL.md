# 辅助 · 起草 /goal 自驱指令

**目标：把"你继续做吧"这种含糊的自我驱动，换成一段有终点、有验证、有边界的 goal 文本。**
goal 让会话跨轮自动续跑，它**不能**替你跳过门禁与审查——只是把"什么时候算做完"写死。

## 先问清三件事（一次问完，用 `ask_user_question`）

1. **终点**：什么状态算完成？（一条可观察的现象，不是"做得差不多了"。）
2. **验证**：谁用什么命令/什么观察来判定完成？（本模式的 `pc.mjs gate --stage verify` + 真机现象是默认答案。）
3. **边界与轮次**：明确不做的事；最多自动跑几轮（建议 5–10 轮，按任务数估）。

## 产出：一段可直接粘的 /goal 文本

```markdown
/goal 按「插件创造模式」的流水线把 <项目名> 做到交付：
目标：<一句话终点，可观察>
判据：<逐条列 docs/01-需求.md 里的成功判据编号；完成 = 每条都有证据或明确标注未验证>
验证：每阶段收口必须跑 node $env:DSH_HOME\plugin-creator\gates\pc.mjs gate --stage <阶段> --project <目录>，
      退出码 0；每个开发任务必须派 subagent 独立审查并过冻结核对。
边界：<不做的事，至少 3 条>；不新增未写入 docs/03-计划.md 的任务；不修改已冻结的产物。
轮次：最多 <N> 轮自动推进；每轮结束把当前阶段写在 <目录>\.plugin-creator\state.json 里。
卡住：连续 3 轮同一阻塞条件（缺权限/缺凭据/缺浏览器控制）才停下报告，并写清缺什么。
```

同时给出一条 `create_goal` 用的紧凑 objective（供你直接调用工具）：

```
objective: 在插件创造模式下推进 <项目名> 直到交付：完成 docs/01..05 六个阶段文档（含 01b 现成插件调研），每个开发任务经独立审查且阻断 Finding 清零，
每次阶段收口通过 pc.mjs gate，最终交付含安装态证据、未验证项与回退点；调研结论为「采用现成插件」时按该路径收尾，不强行自研。
```

## 写作标准

- 终点必须**可观察**：能被一条命令或一次肉眼观察判定。
- 验证必须**可执行**：写清哪条命令、什么退出码、什么现象。
- 边界必须**否证得了**：像"不新增计划外任务""不改已冻结文件"这种，机器和人才能判断有没有越界。
- 必须写**卡住条件**：什么情况下允许停下来问人（否则它会一直绕圈子烧 token）。
- 必须写**轮次上限**。

## 不许做的事

- 不许把 goal 当成"跳过审查"的许可。goal 只改变"谁在什么时候催下一轮"，不改变阶段门禁与审核层。
- 不许写"做到最好""尽量完善"这类没有终点的目标。
- 不许把用户的原始愿望原样抄进 objective；先压成判据再写。
- 不许为了让它继续跑就放宽判据——那是造假，不是自动化。

## 收尾

起草完给用户看一次，得到确认再调用 `create_goal`（长项目）或用 `/goal` 命令。之后每一轮开始先读 `.plugin-creator/state.json` 确认阶段，再按 `plugin-creator` 的路由继续。
